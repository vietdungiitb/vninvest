# 11.01 — Quy Trình Phát Triển

> ⏳ STUB Phase 1. Quy trình đang chạy nằm ở `docs/AGENT_PROTOCOL.md` (multi-agent:
> claim → branch → code → gate sau rebase → PR) và `AGENTS.md` (môi trường, gate).
> Phân hệ này tóm tắt cầu nối giữa quy trình đó với bộ hồ sơ này.

## 1. Vòng đời một slice (code + docs cùng một PR)

1. Nạp `project-lessons` theo tag → ghi `Lessons áp dụng` vào plan.
2. Khai claim (`docs/CLAIMS.md`), branch `feat/<slice>-<agent>`.
3. Đọc phân hệ liên quan trong bộ này trước khi code (biết "đang ở đâu").
4. Code xong: chạy tools docs (`--write` nếu đổi số liệu, rồi `--check` exit 0).
5. Gate sau rebase → claim `done` → push → PR → merge → append ledger Entry.

## 2. Khi sửa code mà tài liệu liên quan đã lệch

Xử lý lệch **trước** (chạy `--check` đỏ từ đầu ⇒ sửa chồng lên là sai — xem
`00.03` §3.1). Không dùng `--no-verify` để lách hook trừ khi ghi lý do vào
commit body.

## 3. Việc của slice phát triển

Chi tiết hóa: checklist Definition-of-Done theo loại slice (FE/BE/docs),
quy ước đặt tên file, EOL (LF cho `.md` mới — L-T01), và quy trình mentor người mới.
