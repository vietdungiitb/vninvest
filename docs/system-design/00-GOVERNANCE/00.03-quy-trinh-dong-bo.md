# 00.03 — Quy Trình Đồng Bộ Tài Liệu Với Code

> ★ **Đọc trước khi sửa code.** Tài liệu viết tay không thể tự biết code đã đổi —
> lệch là không tránh khỏi, chỉ có thể phát hiện sớm hoặc không. Bằng chứng: ngày
> 2026-10-14, `docs/architecture/README.md` §0.4 (đo 2026-10-03) đã lệch 4/9 số
> liệu so với code (routes 1029→1473, core_v1 609→615, compose 8→10, web files
> 516→563 — đo bằng `docs/architecture/tools/measure_repo.py`). Chính sách này
> tồn tại để bộ hồ sơ mới không chết theo cùng một cách.

---

## 1. Nguyên tắc: máy đo cái đo được, người viết cái không đo được

| Loại thông tin | Ai chịu trách nhiệm | Vì sao |
|---|---|---|
| Số lượng, danh sách, trạng thái | **Máy** (`_meta/tools/`) | Đo lại 1 giây, không thể sai |
| Quyết định thiết kế và **lý do** | **Người** (+ ADR) | Máy không biết vì sao chọn |
| Rủi ro, nợ kỹ thuật | **Người** | Máy không đánh giá mức độ |
| Số liệu runtime (p95, tải) | **Người + công cụ đo** | Chỉ biết sau khi chạy thật |

⇒ **Đừng** viết tay một con số mà máy đo được. Viết tay nó là tự tạo ra một điểm
lệch chờ đổi.

## 2. Ba lớp tài liệu

```
Lớp 1 — ĐỊNH NGHĨA   docs/saas_design_pack/ + plan đã duyệt  (viết tay, trước khi code)
Lớp 2 — HIỆN TRẠNG   _meta/ + danh mục máy sinh            🤖 máy sinh
Lớp 3 — PHÂN TÍCH    01…13, MODULES/                        ✍️ người viết
```

Khi **Lớp 1** và **Lớp 2** mâu thuẫn:

| Tình huống | Ai đúng | Hành động |
|---|---|---|
| Code chưa làm như đặc tả | **Lớp 1** | Đặc tả là hợp đồng. Sửa code, hoặc sửa đặc tả **có quyết định** |
| Code làm khác đặc tả | **Lớp 3** | Ghi vào `13.02` nợ kỹ thuật hoặc mở câu hỏi |
| Đặc tả vốn đã sai | **Lớp 1** | Sửa đặc tả **kèm ADR**, không sửa ngầm |

> Mấu chốt: **không có tình huống nào mà "cứ để vậy" là câu trả lời đúng.**

## 3. Quy trình bắt buộc khi sửa code

### 3.1. Trước khi viết

```bash
node docs/system-design/_meta/tools/check-system-design.mjs --check
```

Cổng **đỏ ngay từ đầu** (trước khi bạn sửa gì) ⇒ tài liệu đã lệch từ trước. Xử lý
cái đó **trước**, không sửa chồng lên.

### 3.2. Sau khi viết

```bash
node docs/system-design/_meta/tools/check-system-design.mjs --write   # sinh lại danh mục
node docs/system-design/_meta/tools/check-system-design.mjs --check    # phải exit 0
```

### 3.3. Trước khi mở pull request

| Bạn đã đổi | Cập nhật |
|---|---|
| Model, migration, app, compose, beat | Máy sinh lại — **không sửa tay** con số trong tài liệu |
| Quy tắc nghiệp vụ | `04.02`, `05.01`, dossier trong `MODULES/` |
| Kiến trúc, lựa chọn công nghệ | `02.01` + **ADR mới** trong `00-GOVERNANCE/adr/` |
| Viết một con số vào tài liệu | Thêm mục vào `_meta/claims.json` để máy kiểm (§5) |
| Phát hiện nợ kỹ thuật | `13.02` |
| Phát hiện lỗ hổng / rủi ro bảo mật | `10.03` (khi có) + báo ngay, không chờ slice |

## 4. Cổng chặn: `--check` bắt những gì

| Loại | Cách bắt |
|---|---|
| Danh mục cây tài liệu lạc hậu | Sinh lại `inventory.json` rồi so (chuẩn hóa CRLF, bỏ dòng thời gian khi so) |
| Liên kết nội bộ chết | Quét liên kết Markdown tương đối, resolve từ file chứa nó |
| Citation `path:line` chết/vượt dòng | Tồn tại + nằm trong bounds (kể cả tên đơn qua chỉ mục basename; mơ hồ ⇒ lỗi) |
| Trùng chủ đề | Trùng khóa tên file hoặc trùng H1 trong cùng nhóm |
| Tuyên bố viết tay sai | Đọc `_meta/claims.json`, đo lại từng `fact`, so `expected` |

Ba kỹ thuật chống báo động giả (kế thừa từ vnsaas): so sánh **nội dung** chứ không
so byte (chuẩn hóa `\r\n` → `\n`, bỏ BOM); chỉ ghi **số dòng** thay vì byte; mốc
thời gian sinh dùng token thay khi so.

## 5. Thêm một tuyên bố vào sổ đối chiếu

Khi viết một con số vào tài liệu — *"hiện có 15 app"* — hãy **khai** nó để máy canh
(`_meta/claims.json`):

```jsonc
{
  "id": "C-001",
  "doc": "docs/system-design/01-SYSTEM-OVERVIEW/01.01-tom-tat-dieu-hanh.md",
  "docQuote": "15 Django app nghiệp vụ",   // đúng NGUYÊN VĂN một đoạn trong doc
  "fact": "djangoApps",                    // khóa đo trong check-system-design.mjs
  "expected": 15
}
```

> **Sửa TÀI LIỆU. Đừng sửa `claims.json` cho xanh.** Sửa `claims.json` để xanh là
> xóa chứng cứ. Trường hợp duy nhất được sửa `claims.json`: **tài liệu đúng mà
> phép đo sai** — khi đó sửa phép đo và ghi lại lý do.

## 6. Quy tắc bảo vệ trích dẫn `file:line`

Tài liệu trong bộ này trích dẫn nhau và trích dẫn code bằng `file:line`:

| Quy tắc | Vì sao |
|---|---|
| **Bổ sung ở CUỐI** file, không chèn giữa | Chèn làm mọi trích dẫn phía sau sai dòng |
| Không sửa dòng đã có trích dẫn trỏ tới | Sửa là hỏng trích dẫn |
| Sổ append-only không sửa dòng cũ | Không có cách nào sửa trích dẫn cũ trỏ vào |

## 7. Giới hạn thật (ghi ra thay vì giấu)

- Máy chỉ bắt tuyên bố **đã khai**. Tài liệu sai mà không có con số, kết luận suy
  luận sai, ví dụ sai mà đúng hình thức — máy không bắt được. Bù bằng audit định
  kỳ + khai tuyên bố khi viết mới. Không có cổng nào thay được việc đọc.
- Các số **biến động nhanh** (`routes_total`, `web_src_tracked`, `docs_md_total`)
  chỉ nằm ở bảng VOLATILE trong `freshness-report.md` (thông tin, không chặn) và
  ở ảnh chụp có ghi ngày (như `00.04` §1). Chặn chỉ áp dụng cho số kiến trúc
  chậm đổi đã khai trong `claims.json`.
