## 2. Kịch bản A — Deploy lỗi (code mới crash-loop)

1. Xác định commit lỗi cuối: log `core-api` có traceback + `RestartCount` tăng
   (cách đo ở `09.01` §2 bước 3).
2. Trên VPS `/opt/vninvest`: `git reset --hard <commit-xanh-trước-đó>`.
3. Chạy lại `bash scripts/deploy-staging.sh` (chờ healthy như deploy thường).
4. Verify 4 điểm `09.01` §2 bước 4. Revert PR lỗi trên GitHub sau.

## 3. Kịch bản B — Migration lỗi (migrate fail giữa chừng)

1. Dừng deploy (không chạy tiếp khi migrate đỏ).
2. Lùi migration bằng Django chuẩn: `manage.py migrate <app> <migration-trước>`
   trong container `core-api`.
3. ⚠ Backfill dữ liệu (vd `0022`) có thể không lùi sạch — đọc `forwards()` trước
   khi lùi; không chắc thì dừng và gọi Tech Lead (không đoán).
4. Reset code + deploy lại (kịch bản A bước 2-4).

## 4. Kịch bản C — Mất dữ liệu (restore từ backup)

1. Chọn bản backup: file gzip mới nhất (local) hoặc S3/R2 (`BACKUP_S3_BUCKET`).
2. Chạy `bash scripts/test-backup-restore.sh <BACKUP_DATE>` trước — restore vào
   DB test để xác nhận file dùng được (không restore thẳng prod khi chưa thử).
3. Dừng ghi: tắt worker/beat (tránh ghi mới trong lúc restore).
4. Restore vào DB staging/prod bằng `pg_restore`/`psql` tương ứng định dạng dump.
5. Verify: đếm `LedgerEntry`/`Portfolio` + mở app kiểm tra đọc/ghi, rồi bật lại worker.

## 5. Danh sách KHÔNG làm

- Không restore đè prod khi chưa thử file trên DB test.
- Không lùi migration dữ liệu khi chưa đọc `forwards()`/`backwards()`.
- Không xóa backup cũ khi chưa biết retention (❓ chính sách retention chưa có —
  slice vận hành bổ sung).

## 6. Việc còn lại (slice vận hành)

Chốt RTO/RPO với Owner · diễn tập full 3 kịch bản trên staging (ghi thời gian thật)
· chính sách retention backup · runbook failover DB.
