# 09.01 — Triển Khai Và Vận Hành

> Bản đồ + quy trình triển khai staging/prod. Chi tiết lệnh từng bước ở
> `docs/STAGING_VPS_RUNBOOK.md` và `scripts/deploy-staging.sh` (không copy dài
> sang đây — một khái niệm, một định nghĩa).

## 1. Bản đồ triển khai

- **Staging (mặc định(editorial, mọi chạy thử):** VPS `14.225.255.47`,
  `https://docker.edusuccess.vn`, repo `/opt/vninvest` (branch `dev`),
  deploy bằng `bash scripts/deploy-staging.sh` — xem `docs/STAGING_VPS_RUNBOOK.md`.
- **Stack:** 10 compose stack (máy đo — claim `C-004`), gồm app + db + redis +
  pgbouncer + proxy + monitor.
- **Giới hạn RAM staging:** `CORE_API_MEM_LIMIT=2g` trở lên (full BE suite cần
  ≥ 2 GiB; exit 137 = OOM — xem `compose.staging.env.example`).

## 2. Quy trình deploy chuẩn (staging)

1. Commit lên `dev` qua PR đã CLEAN (CI `scan` xanh).
2. Trên VPS: `git fetch` + `reset --hard origin/dev` trong `/opt/vninvest`.
3. Chạy `bash scripts/deploy-staging.sh` — script tự chờ API healthy, kiểm tra
   crash-loop/OOM (`RestartCount`, `OOMKilled`), báo deploy xong.
4. Verify: `/` và `/health` trả 200, route mới trả 200, queue redis rỗng,
   log `core-api` không traceback.

## 3. Giám sát và vận hành

- Prometheus + Grafana (metrics app/infra), `redis-exporter`,
  `queue-drain-monitor` (hàng đợi Celery).
- Lịch beat là nguồn sự thật của ingest (42 lịch — claim `C-005`).
- Quay lui (rollback): xem `09.02-runbook-khoi-phuc.md` (3 kịch bản: deploy lỗi,
  migration lỗi, mất dữ liệu). Diễn tập full + retention backup còn mở (§6).
