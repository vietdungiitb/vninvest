# 10.01 — Chiến Lược Kiểm Thử

> Nguyên tắc: gate chỉ có giá trị khi chạy đúng thời điểm (sau rebase) trên code
> thật — không báo PASS cho thứ chưa chạy (L-G02). Fail-closed: exit ≠ 0 là dừng.

## 1. Các tầng kiểm thử đang chạy

| Tầng | Lệnh | Ghi chú |
|---|---|---|
| BE unit/integration | `manage.py test` (Postgres riêng, `CORE_DATABASE_URL` + `DJANGO_DEBUG=1`) | Không chạy được trên SQLite (`array_agg`); full suite cần RAM ≥ 2 GiB |
| BE check nhanh | `manage.py check` + `makemigrations --check` | Chặn migration thiếu/sai trước khi test |
| FE component | `npm run test:components` (vitest) | Khóa render + identity i18n |
| FE typecheck/lint/build | `tsc --noEmit`, `eslint`, `npm run build` | Build = `tsc && vite build` |
| E2E | Playwright `packages/web/tests/visual/` (vd `portfolios-manage.spec.ts` 8 case) | Cần staging + seed đúng + dọn dữ liệu sau chạy |
| Gate tổng | `node scripts/pre-push-gate.mjs` (22 gate) + `check-system-design.mjs --check` | Fail-closed, chạy ở pre-push |
| Bảo mật | `scan-secrets` (CI + pre-push, ~3856 file) | Tracked sạch; history còn secret (P0-SEC-01) |
| Contract FE route | `route-catalog-contract.component.test.ts` | Khóa 2 chiều catalog ↔ `main.tsx` (D-01) |

## 2. Quy trình verify một slice (Definition of Done kiểm thử)

1. Fail-before: chứng minh test đỏ trước fix (sửa code/xóa dòng → FAIL), rồi xanh
   sau fix. Fail-before không có tác dụng (sửa không khớp mà vẫn xanh) thì bỏ.
2. Chạy đúng phạm vi: file đổi BE ⇒ test app đó; FE ⇒ component + build;
   docs ⇒ `--check`.
3. Gate sau rebase, không tái dùng số liệu trước rebase (L-G01).
4. Artifact verify trong container khi đụng FE deploy (`docker exec` đọc assets,
   không tin `dist/` trên host).
5. Ghi trung thực: PASS / FAIL / CHƯA CHẠY + lý do. Flake ghi rõ file + lần chạy.

## 3. Nợ kiểm thử (vào `13.02` khi có mã N-xxx)

- Ba app 0 test file: `advisory`, `advertising`, `support` (đo ở `04.01`).
- Ma trận test theo app + độ phủ: viết ở slice kiểm thử (chưa có).
