# 10.01 — Chiến Lược Kiểm Thử

> ⏳ STUB Phase 1. Nguyên tắc: gate chỉ có giá trị khi chạy đúng thời điểm (sau
> rebase) trên code thật — không báo PASS cho thứ chưa chạy (L-G02).

## 1. Các tầng kiểm thử đang chạy

| Tầng | Lệnh | Ghi chú |
|---|---|---|
| BE unit/integration | `manage.py test` (Postgres riêng, `CORE_DATABASE_URL` + `DJANGO_DEBUG=1`) | Không chạy được trên SQLite (`array_agg`) |
| FE component | `npm run test:components` (vitest) | |
| E2E | Playwright `packages/web/tests/visual/` | Cần staging + seed đúng |
| Gate tổng | `node scripts/pre-push-gate.mjs` + `node docs/system-design/_meta/tools/check-system-design.mjs --check` | Fail-closed |
| Bảo mật | `scan-secrets` (CI + pre-push) | Tracked file sạch; history còn secret (P0-SEC-01) |

## 2. Việc của slice chất lượng

1. Ma trận test theo app (app nào có/không có test, độ phủ).
2. Sổ findings kiến trúc (vad từ audit) + trạng thái sửa.
3. Quy trình E2E chuẩn (seed, dọn dữ liệu test, flake đã biết).
