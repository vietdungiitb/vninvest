# Evidence — DataOps inventory treo do external KBS call (2026-11-20)

## 1. Reproduce (VPS staging, Playwright + JWT staff thật)

- URL `https://docker.edusuccess.vn/operations-center?tab=dataops`, chờ 45s.
- Request `GET /core/v1/operator/soc/dataops/inventory/` **không có response** (không `RESP`/`requestfinished` dù đã gửi `REQ`); 4 endpoint khác (`run-logs`, `coverage`, `runtime-config`, `queue-tiers`) 200 trong ~5s.
- DOM: 4 skeleton cards vẫn còn; `HAS_4_6M=false`. Header đã đúng "Chưa theo dõi" (R1 từ PR #442).
- Log daphne: `uri=/core/v1/operator/soc/dataops/inventory/ ... took too long to shut down and was killed`.
- Django test client (`force_login`, HTTP_HOST đúng) → 200 `{"data":{"summary":{"total_rows":4582503,...}}}` ⇒ shape API đúng, lỗi ở external blocking.

## 2. Root cause

`service_ops/views/dataops_inventory.py:57-59` gọi `fetch_symbol_group_members()` cho mỗi `PREDEFINED_SYMBOL_GROUPS`; hàm này (`market_data/vnbroker_adapter.py:840-925`) probe KBS adapter + `fetch_listing_symbols` có retry. Khi upstream chậm, view treo ⇒ `loading.inventory` không bao giờ false ⇒ FE dính skeleton. Log staging cũng có `fetch_symbol_group_members VN50 via KBS failed: RetryError[...]`.

DB đã có SSOT: `CachedSymbolGroup` 22 rows / `CachedSymbolGroupMember` 3968 rows; predefined groups đều có cache (`VN30`, `VNX50`/`X50`, `VN100`, `HOSE`, `HNX`, `UPCOM`).

## 3. Fix

- Thêm `_db_group_symbols(group_id)` trong `dataops_inventory.py`: đọc `CachedSymbolGroupMember` (và `CustomSymbolGroup.clean_symbols()` cho `custom_*`), alias `vn50 → VNX50`, fallback `group_code`. **Không gọi KBS**.
- Bỏ import `fetch_symbol_group_members` khỏi `get()`, thay bằng helper. Không migration, không đổi shape/route.

## 5. Bổ sung sau PR #444/#445 — tối ưu & verify staging

- Profile trên DB staging (Redis/Django) khiến view mất **27.6s**: `by_year` `DATE_TRUNC + COUNT(DISTINCT)` **8.1s**, tổng aggregate **4.0s**, mỗi group aggregate ~2.3s.
- PR #445: cache payload 5 phút trên Redis (key `soc:dataops:inventory:v1`, fail-soft) + bỏ `COUNT(DISTINCT symbol)` ở `by_year` (FE chỉ dùng `rows`) và lấy `total_symbols` từ `StockProfile`.
- Đo thật sau deploy: cold **22.71s** → warm **3.61s** (cùng lệnh time-view). BE test vẫn OK sau tối ưu.
- Playwright trên staging sau deploy: `RESP 200 operator/soc/dataops/inventory/`, `HAS_4_6M=true`, `HERO_VALUES=["4.6M","0","0","1"]`, không skeleton, không banner lỗi. Header vẫn "Chưa theo dõi" (đúng R1).

## 6. CHƯA CHẠY / rủi ro

- Full BE suite / E2E — không chạy trong slice này.
- Không sửa `vnbroker_adapter.py` — nơi khác vẫn dùng external call; nếu KBS chết, các luồng đó vẫn chậm (ngoài scope).
- Cold cache vẫn ~22s (bảng 4.5M row); đã có cache 5 phút nhưng request đầu sau flush Redis vẫn chậm. Cần tối ưu sâu hơn (materialized summary / index) nếu muốn <5s cold — ticket riêng.
- Nếu cache nhóm chưa sync, inventory trả `symbol_count=0` cho nhóm đó thay vì treo — chấp nhận được (fail-soft).
