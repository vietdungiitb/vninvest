**Lessons:** [L-V01, L-V02, L-V04, L-007]. Dựa trên `SSOT_ADJUSTMENT_DESIGN_REV2` D-01/D-02/D-04 và `SSOT_DECISIONS_REV2` D-08.

## 1. Mục tiêu
Thay thế 3 đường ghi rời rạc (`rebase_symbol_from_cafef`, `cafef/fallback`, `apply_adjustments`) bằng **một** service thuần:
```
adj_close(t) = base_close(t) * Π f(e) với e.ex_date > base_as_of(t)
```
D-08 Anchor A: toàn chuỗi có `base_as_of` cùng vintage; CafeF chỉ đối chiếu.

## 2. Công thức (D-02)
```
D = Σ cash_amount_per_share
I2 = Σ stock_ratio_pct / 100
I1 = rights_ratio_pct / 100 ; P_issue = rights_issue_price (sẽ thêm cột ở phase này)
P_prev = base_close của phiên liền trước ex_date có base_as_of == date
f(e) = (P_prev + I1*P_issue - D) / (P_prev * (1 + I1 + I2))
```
Nếu event `parse_status != structured` hoặc `ambiguous_*` hoặc thiếu `P_issue` ⇒ `AdjFactor.status=PARTIAL`, **giữ chuỗi cũ**, alert — **không reset `adj_close=NULL`** như `adjustment.py:102-109` hiện làm.

## 3. AC Given/When/Then
- **AC1**: recompute 2 lần liên tiếp cùng input → cùng output (idempotent), `adj_version` tăng đúng 1/lần.
- **AC2**: FPT ex-date 2026-11-27 (`DIV 1000`, P_prev 44500) → `adj_close(2026-11-26)=43500`.
- **AC3**: dòng có `base_as_of >= ex_date` **không** bị nhân thêm factor (0 double-adjust).
- **AC4**: event PARTIAL ⇒ 0 UPDATE, audit reason `PARTIAL_EVENT`.
- **AC5** (D-04): sample **1 symbol**, cửa sổ `[ex_date-10 phiên, ex_date+2]`, so **return-ratio** quanh ex-date:
  `| (adj_new(d_prev)/adj_new(d_ex)) / (prov(d_prev)/prov(d_ex)) - 1 | <= 0.005`.
  Nếu `prov(d_prev)==raw_prev` (provider chưa cập nhật) ⇒ `PENDING_PROVIDER_SYNC`, cho phép commit khi event structured + hẹn verify 6h/24h; **không báo công thức sai oan**. Canary 24 mã/ngày là job riêng.
