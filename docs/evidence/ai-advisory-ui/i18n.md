# i18n + parity (W5)

## Gate cũ là gate chết — bằng chứng

Chạy `npm run i18n:scan` trước khi sửa:

```
i18next-scanner: SyntaxError: Unexpected token 'c', "const vi ="... is not valid JSON
i18next-scanner: SyntaxError: Unexpected token 'c', "const en ="... is not valid JSON
...
i18next-scanner: Added a new translation key { "error": "Không tải được backtest." } to "src/i18n/vi.js"
I18N_EXIT=0
```

Ba vấn đề riêng biệt:
1. `resource.loadPath` trỏ `src/i18n/{{lng}}.js` — file locale là **ESM JavaScript**
   (`const vi = {...}`), scanner `JSON.parse` nên luôn lỗi.
2. `src/i18n/**` nằm trong `input`, tức scanner quét chính output của nó.
3. **Exit code 0 dù parse lỗi** → gate không bắt được gì. Kiểm chứng: sau khi chạy,
   `git diff --numstat` cho `vi.js`/`en.js` **không đổi**, tức scanner chỉ in log rồi bỏ qua.

## Cách sửa

- `i18next-scanner.config.cjs`:
  - thêm `!src/i18n/**` vào `input` (locale file là output, không phải source để quét);
  - trỏ `resource.loadPath`/`savePath` sang `node_modules/.cache/i18next-scanner/` (đã gitignore)
    để scanner chỉ sinh báo cáo, không đụng file locale thật.
- Xoá 2 artifact `src/i18n/vi.json` / `en.json` do config cũ ghi ra (đã gitignore).
- Thêm gate mới `scripts/check-i18n-hardcoded.mjs`, gắn vào `check:shell` sau `i18n:scan`.

## Gate mới — chứng minh nó fail thật

Tiêm 1 chuỗi tiếng Việt có dấu vào `TrustTelemetryPanel.js`:

```
src\components\advisory\TrustTelemetryPanel.js (1)
  123: const canh_bao = 'Không tải được dữ liệu';

TOTAL_HARDCODED_VI=1
EXIT=1
```

Gỡ lại:

```
OK: 0 chuoi tieng Viet hardcode trong 15 file (src/components/advisory)
EXIT=0
```

Gate bỏ qua có chủ đích: dòng đã gọi `t(...)`, dòng có `defaultValue`, dòng khai báo
`defaultLabel`/`defaultDescription` (dữ liệu fallback cho pattern
`t(key, { defaultValue: defaultLabel })`), dòng có `className`, dòng comment, file test.

## Phát hiện quan trọng: khai báo trùng key trong object

Khi thêm key mới, tôi đã vô tình khai báo `risk: {...}` lần thứ hai trong cùng object
`aiAdvisory`. JavaScript cho phép, khối sau **ghi đè** khối trước, làm mất
`risk.title` / `conservative` / `balanced` / `aggressive`. Test
`whale-advisory-i18n-batch2.component.test.ts` bắt được ngay (13 key thiếu).

Đã gộp lại thành một khối `risk` duy nhất. Cùng kiểu lỗi cũng xảy ra với `delete`,
`explainability`, `telemetry`.

Vì vậy đã thêm script phát hiện key trùng ở độ sâu 1 trong một namespace:

```powershell
node <script quét depth-1 key của aiAdvisory>
# vi.js: depth1 keys=23 — khong co key trung
# en.js: depth1 keys=23 — khong co key trung
```

**Bài học**: khi thêm key vào namespace đã có, phải mở khối cũ thêm vào, không tạo khối mới
cùng tên ở cuối. Test parity key-set **không** bắt được lỗi này (vì nó chỉ so tập key cuối
cùng, hai bên đều mất key giống nhau) — cần script riêng.
