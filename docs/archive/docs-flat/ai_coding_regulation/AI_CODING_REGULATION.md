# AI Coding Regulation: Explicit Consent Only

This document defines the mandatory interaction protocol between the AI (Antigravity) and the USER for the VNInvest repository.

## 1. The Golden Rule
**Antigravity MUST NOT modify any source code files without explicit, affirmative consent from the USER.**

## 2. Default State: Audit & Documentation
*   By default, all AI activities are restricted to **Audit and Planning** only.
*   Research findings, technical audits, and implementation plans must be presented as Markdown documents (artifacts) or text responses.
*   **Mandatory Persistence**: Every **Implementation Plan** generated by the AI MUST be saved as a `.md` file in the `docs/` directory to ensure historical tracking and repository-level visibility.
*   **Mandatory Documentation Bundle**: When a plan is required, the AI MUST generate the complete triad: **Implementation Plan**, **Tech Spec**, and **Taskboard**.
*   Proposed code changes should be presented as snippets or description within these documents, not applied to the actual codebase.

## 3. Workflow for Code Modification
1.  **Research**: AI analyzes the request and researches the codebase.
2.  **Audit/Plan**: AI produces a report or implementation plan.
3.  **User Review**: USER reviews the documentation.
4.  **Explicit Command**: AI waits for a specific command to proceed (e.g., "Code đi", "Proceed with implementation", "Thực hiện").
5.  **Execution**: Only after the command is received, the AI may use code-editing tools.

## 4. Consequences of Violation
*   If code is modified without explicit consent, the AI must acknowledge the error and offer a rollback.
*   The AI must prioritize integrity and user control over speed of delivery.

## 5. Markdown Docs Auto-Audit Trigger (Mandatory)

**Quy định bắt buộc:** Bất kỳ file `.md` nào trong thư mục `docs/` khi **được tạo mới** hoặc **bị thay đổi nội dung** đều phải được AI tự động audit và lập báo cáo chi tiết.

### Phạm vi áp dụng
- Áp dụng cho mọi nguồn thay đổi, **không phụ thuộc tác nhân thực hiện**:
  - USER chỉnh tay.
  - AI chỉnh sửa.
  - Script/tool tự động.
  - Git merge, pull, rebase, cherry-pick.

### Yêu cầu thực thi
- Tạo/cập nhật báo cáo audit mô tả:
  - Mục tiêu thay đổi.
  - Tác động/rủi ro.
  - Danh sách file liên quan.
  - Hạng mục cần follow-up.
- Cập nhật `docs/CODE_CHANGE_AUDIT_LEDGER.md` cho mỗi đợt thay đổi.
- Đồng bộ danh sách file đã audit trong `PROGRESS_DASHBOARD.md`.

### Điều kiện miễn trừ
- Không có miễn trừ mặc định.
- Nếu không thể audit ngay (ví dụ workspace lỗi), phải ghi rõ lý do và mở mục follow-up bắt buộc.

## 6. Pagination Standard

**Quy định bắt buộc:** Mọi module, trang, hoặc panel có danh sách phân trang đều phải sử dụng component dùng chung sau đây. **Nghiêm cấm tạo inline pagination riêng lẻ.**

### Component chuẩn
```
frontend/src/components/shared/PaginationBar.jsx
```

### Cách dùng

**Offset-mode** (biết tổng số bản ghi — dùng cho danh sách client-side):
```jsx
import PaginationBar from '../shared/PaginationBar';

<PaginationBar
  mode="offset"
  total={totalItems}
  page={currentPage}        // 1-based
  size={pageSize}
  onPageChange={setCurrentPage}
  onSizeChange={handleSizeChange}
/>
```

**Cursor-mode** (cursor-based API — dùng cho stream/realtime):
```jsx
<PaginationBar
  mode="cursor"
  currentPage={currentPage}
  hasPrev={hasPreviousPage}
  hasNext={hasNextPage}
  hasLast={hasLastKnownPage}
  loading={isLoading}
  onFirst={goToFirst}
  onPrev={goToPrev}
  onNext={goToNext}
  onLast={goToLast}
  pageSize={pageSize}
  onSizeChange={setPageSize}
/>
```

### Giao diện chuẩn
- **Page size:** combobox `<select>` với các tùy chọn `[5, 10, 15, 20]`.
- **Nút điều hướng:** icon SVG (không dùng text), có `title` tooltip. Thứ tự: ⏮ Đầu · ◀ Trước · ▶ Tiếp · ⏭ Cuối.
- **Nút Tiếp:** hiển thị spinner khi đang loading.
- **Disable logic:** nút disabled khi không có trang tương ứng.

### Modules đã tuân thủ (cập nhật 2026-04-21)
| Module | File | Mode |
|--------|------|------|
| Trung tâm cảnh báo | `components/UnifiedAlertCenter.jsx` | cursor |
| Position Deck | `components/modern/ModularPositionDeck.jsx` | offset |

## 7. Single Source of Truth (SSOT) for Core Intelligence Flows (Mandatory)

**Quy dinh bat buoc:** Moi tinh nang moi hoac sua doi tinh nang lien quan du lieu thi truong/phan tich phai noi vao dung nguon SSOT duoi day. Khong duoc tao luong du lieu song song cho cung nghiep vu.

### 7.1. SSOT domains bat buoc
- `vnbroker adapter` la SSOT cho du lieu market provider (quote/price-board/intraday provider access).
- `whale alert` la SSOT cho logic canh bao whale theo pipeline hien hanh.
- `darkmoney flow` la SSOT cho logic dong tien lon/dong tien toi theo pipeline hien hanh.
- `ai advisory` la SSOT cho logic tong hop/phan tich/khuyen nghi AI advisory.

### 7.2. Yeu cau implementation
- Moi feature lien quan toi domain nao phai consume du lieu va contract tu SSOT domain do.
- Khong duoc duplicate nghiep vu cung domain o mot module khac de tinh toan lai ket qua.
- Khong duoc dung endpoint/cache/model song song neu da co endpoint/cache/model canonical cua domain.
- Neu can transform du lieu phuc vu UI, transform o lop presentation, khong thay doi su that nghiep vu cua SSOT.

### 7.3. Nghiêm cam
- Cam tao "ban sao" pipeline cho whale alert, darkmoney flow, ai advisory, hoac provider call bypass `vnbroker adapter`.
- Cam de hai nguon tinh toan cung mot chi so va co the cho hai ket qua khac nhau.

### 7.4. Dieu kien merge bat buoc
- PR phai chi ro feature dang noi vao domain SSOT nao.
- Neu co thay doi contract, phai cap nhat dong bo test + docs + audit ledger.
- Neu phat hien conflict ket qua giua hai luong, phai quy ve SSOT va xoa luong non-SSOT truoc khi merge.

### 7.5. Hard rules cho Global Market Data Matrix SSOT (Khong ngoai le)
- `global symbol matrix` / `global symbol registry` la SSOT duy nhat cho du lieu thi truong dung chung toan he thong.
- Global matrix phai la hop nhat persistent cua moi demand source hop le: system defaults, admin global groups, holdings, watchlists, tracked symbols, alerts, va cac nguon global da duoc phe duyet.
- User khong duoc so huu ban sao market-data rieng; user chi so huu membership/metadata rieng, con gia/history/intraday/facts/snapshots phai doc tu shared global layer.
- Watchlist/tracked/holding/alert chi la event promote demand vao global matrix; nghiem cam tao crawl silo rieng theo user/workspace.
- `ScrapeMatrix`, queue snapshot, run-log, va moi execution state chi la lop van hanh; khong duoc dung de thay the persistent universe SSOT.
- Mọi read path san pham phai uu tien global facts/snapshots/history/materialized data; nghiem cam per-user recrawl neu da ton tai shared facts-first path hop le.
- Planner cao du lieu bat buoc coverage-gap/freshness-gap driven tren global registry; cam full-scan ad hoc va overwrite mu quang.
- Symbol chi duoc ha uu tien hoac roi active crawl set khi tat ca demand source het hieu luc va decay window da qua; khong drop ngay vi mot user remove.
- Thu tu uu tien bat buoc: dung shared SSOT truoc, tranh crawl lap sau, roi moi toi uu UX/SLA/chi phi.

### 7.6. Dieu kien merge bo sung cho market-data SSOT
- PR phai chi ro demand source nao duoc them/sua/remove khoi global matrix.
- PR phai chi ro read path nao doc tu global registry/facts layer va khong duoc mo them per-user provider call path.
- PR chạm ingest/planner phai co evidence `missing-only` hoac `coverage-gap` semantics; neu khong chung minh duoc thi block merge.
- PR chạm watchlist/tracked/holding/alert behavior phai duy tri nguyen tac: user event -> global demand promotion -> shared data read path.

### 7.7. Dev Runtime Refresh Hard Rule
- `start_dev.ps1` la entrypoint chuan, bat buoc cho moi lan build/rebuild/restart dev stack trong repo nay.
- AI phai mac dinh chay `./start_dev.ps1` sau runtime/UI/backend slices ma khong can hoi lai USER viec co dung script nay hay khong.
- Khong duoc dung `docker compose ... up/build` truc tiep de thay the workflow dev thong thuong, vi nhu vay bo qua env bootstrap, `VNBROKER_GITHUB_TOKEN` bootstrap, health wait, scheduler drift check, va smoke checks ma `start_dev.ps1` dang so huu.
- `./start_dev.ps1 -SkipBuild` chi duoc dung khi da co rebuild hop le truoc do va muc tieu chi la restart/up; neu co file moi, thay doi image-layer, hoac can chac chan container nhan code moi, phai dung `./start_dev.ps1` ban day du.
- Neu buoc debug can goi `docker compose` truc tiep de forensic `start_dev.ps1` hoac drift compose, AI phai ghi ro ly do lech chuan trong audit ledger va progress dashboard.

## 8. Mandatory Campaign Closure Documentation

**Quy định bắt buộc:** Ngay sau khi hoàn thành việc triển khai code (Execution) và đóng lại một chiến dịch/giai đoạn (Campaign Closure), AI **BẮT BUỘC** phải ghi lại toàn bộ tài liệu phục vụ việc audit và nghiệm thu thành các file vật lý trong thư mục `docs/`.

### Yêu cầu thực thi
- **Thời điểm**: Ngay sau khi đạt Definition of Done (DoD) và trước khi kết thúc phiên làm việc/bàn giao kết quả cuối cùng.
- **Danh mục tài liệu bắt buộc**:
  - `IMPLEMENTATION_PLAN_*.md`: Phản ánh đúng trạng thái thực thi cuối cùng.
  - `TECH_SPEC_*.md`: Đặc tả kỹ thuật chi tiết của giải pháp đã triển khai.
  - `TASKBOARD_*.md`: Ghi nhận trạng thái hoàn thành của từng đầu việc (100% DONE).
  - `WALKTHROUGH_*.md`: Báo cáo tổng kết, bằng chứng verify, screenshot/recording (nếu có).
- **Nguyên tắc**: Đây là quy định cứng, **không có ngoại lệ**. Việc chỉ cung cấp tài liệu dưới dạng artifact tạm thời mà không lưu vào `docs/` được coi là vi phạm quy trình.
