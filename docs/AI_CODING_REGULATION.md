# AI Coding Regulation: Explicit Consent Only

This document defines the mandatory interaction protocol between the AI (Antigravity) and the USER for the VNInvest repository.

## 1. The Golden Rule
**Antigravity MUST NOT modify any source code files without explicit, affirmative consent from the USER.**

## 2. Default State: Audit & Documentation
*   By default, all AI activities are restricted to **Audit and Planning** only.
*   Research findings, technical audits, and implementation plans must be presented as Markdown documents (artifacts) or text responses.
*   **Mandatory Persistence**: Every **Implementation Plan** generated by the AI MUST be saved as a `.md` file in the `docs/` directory to ensure historical tracking and repository-level visibility.
*   Proposed code changes should be presented as snippets or description within these documents, not applied to the actual codebase.

## 3. Workflow for Code Modification
1.  **Research**: AI analyzes the request and researches the codebase.
2.  **Audit/Plan**: AI produces a report or implementation plan.
3.  **User Review**: USER reviews the documentation.
4.  **Explicit Command**: AI waits for a specific command to proceed (e.g., "Code đi", "Proceed with implementation", "Thực hiện").
5.  **Execution**: Only after the command is received, the AI may use code-editing tools.

## 4. Consequences of Violation
*   If code is modified without explicit consent, the AI must acknowledge the error and offer a rollback.
*   The AI must prioritize integrity and user control over speed of delivery.

## 5. Markdown Docs Auto-Audit Trigger (Mandatory)

**Quy định bắt buộc:** Bất kỳ file `.md` nào trong thư mục `docs/` khi **được tạo mới** hoặc **bị thay đổi nội dung** đều phải được AI tự động audit và lập báo cáo chi tiết.

### Phạm vi áp dụng
- Áp dụng cho mọi nguồn thay đổi, **không phụ thuộc tác nhân thực hiện**:
  - USER chỉnh tay.
  - AI chỉnh sửa.
  - Script/tool tự động.
  - Git merge, pull, rebase, cherry-pick.

### Yêu cầu thực thi
- Tạo/cập nhật báo cáo audit mô tả:
  - Mục tiêu thay đổi.
  - Tác động/rủi ro.
  - Danh sách file liên quan.
  - Hạng mục cần follow-up.
- Cập nhật `docs/CODE_CHANGE_AUDIT_LEDGER.md` cho mỗi đợt thay đổi.
- Đồng bộ danh sách file đã audit trong `PROGRESS_DASHBOARD.md`.

### Điều kiện miễn trừ
- Không có miễn trừ mặc định.
- Nếu không thể audit ngay (ví dụ workspace lỗi), phải ghi rõ lý do và mở mục follow-up bắt buộc.

## 6. Pagination Standard

**Quy định bắt buộc:** Mọi module, trang, hoặc panel có danh sách phân trang đều phải sử dụng component dùng chung sau đây. **Nghiêm cấm tạo inline pagination riêng lẻ.**

### Component chuẩn
```
frontend/src/components/shared/PaginationBar.jsx
```

### Cách dùng

**Offset-mode** (biết tổng số bản ghi — dùng cho danh sách client-side):
```jsx
import PaginationBar from '../shared/PaginationBar';

<PaginationBar
  mode="offset"
  total={totalItems}
  page={currentPage}        // 1-based
  size={pageSize}
  onPageChange={setCurrentPage}
  onSizeChange={handleSizeChange}
/>
```

**Cursor-mode** (cursor-based API — dùng cho stream/realtime):
```jsx
<PaginationBar
  mode="cursor"
  currentPage={currentPage}
  hasPrev={hasPreviousPage}
  hasNext={hasNextPage}
  hasLast={hasLastKnownPage}
  loading={isLoading}
  onFirst={goToFirst}
  onPrev={goToPrev}
  onNext={goToNext}
  onLast={goToLast}
  pageSize={pageSize}
  onSizeChange={setPageSize}
/>
```

### Giao diện chuẩn
- **Page size:** combobox `<select>` với các tùy chọn `[5, 10, 15, 20]`.
- **Nút điều hướng:** icon SVG (không dùng text), có `title` tooltip. Thứ tự: ⏮ Đầu · ◀ Trước · ▶ Tiếp · ⏭ Cuối.
- **Nút Tiếp:** hiển thị spinner khi đang loading.
- **Disable logic:** nút disabled khi không có trang tương ứng.
